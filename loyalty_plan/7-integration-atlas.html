The fragility doctrine

Every adapter is someone else's system.

Petpooja ships an API change → our adapter breaks. Meta tightens WhatsApp policy → templates get rejected overnight. Instagram changes story URL format → activity verification stops working. We design every integration as if it will break — because eventually it will.

01Every adapter goes through an internal abstraction. VerificationService, CommsService, POSAdapter. One internal interface, swappable underlying.
02Every external dependency has a manual fallback. Activity auto-verify fails → manual review queue. WhatsApp fails → SMS. POS fails → QR check-in. Customer never sees a hard error.
03Every integration has health monitoring + alerting. We know before the restaurant does. Alert fires when success rate drops below threshold for an hour.
04Never auto-verify with third-party APIs in MVP1. All activity verification is manual until P2 → URL submission, P3 → API checks. Manual is slow, but it never breaks.
AIntegrations live in MVP1

WhatsApp BSP

Interakt or AiSensy · BUSINESS API LAYER
MVP1 · core
Fragility · high Replaceable: yes (Wati, AiSensy, Interakt all interchangeable)
What we use it for

OTP sends. All 5 automated triggers (welcome, 60% nudge, reward unlocked, expiry, win-back). Status webhooks. Opt-out handling.

When it breaks

Templates can be rejected by Meta with 1 day notice. BSP can have outages. Fall back to SMS for T3 + T4 (critical). T1/T2/T5 wait in queue.

Per utility conversation₹0.35 – ₹0.60

Razorpay

PAYMENT REDIRECT · OPTIONAL PER RESTAURANT
MVP1 · optional
Fragility · low Replaceable: yes (PhonePe, Cashfree if needed)
What we use it for

Customer pays the bill through a Loop-rendered page. Payment completion webhook fires → visit + spend logged automatically. Cleanest spend capture without POS.

When it breaks

Webhook delays — our event queue is idempotent, processes when it arrives. Down for hours → restaurants fall back to QR scan + self-entry bill amount.

Per transaction2% + GST · paid by restaurant

Browser push

WEB PUSH · FCM / VAPID
MVP1 · free layer
Fragility · low Free forever · standard browser API
What we use it for

Always-on layer for customers who allow notifications. Lighter-weight reminders that don't justify a WhatsApp message. Strong on Android, inconsistent on iOS.

When it breaks

iOS Safari rejection is the norm — fine, WhatsApp covers it. Android FCM is rock solid.

Cost₹0 · forever

SMS · MSG91 or Exotel

SILENT FALLBACK CHANNEL
MVP1 · fallback
Fragility · low DLT-templated, India-resident
What we use it for

Only when WhatsApp fails. T3 (reward unlocked) and T4 (expiry warning) — the critical triggers. Never primary.

When it breaks

Open rate is 20% vs WhatsApp's 85% — already a degraded experience. Worth having for the rare WhatsApp downtime.

Per message₹0.15 – ₹0.25
BPhase 2 integrations · month 5–8

Petpooja

POS WEBHOOK · BILL CLOSED EVENT
Phase 2
Fragility · high Replaceable per-restaurant only
What it unlocks

Auto-verified visits. Spend per visit. Item-level data → unlocks Bucket 4 product-based rewards (5 cocktails, brunch streak, etc.). Zero staff effort for restaurants on Petpooja.

When it breaks

Petpooja ships an API change → our adapter breaks for all Petpooja restaurants. POSAdapter interface keeps update isolated to one file. Per-restaurant: fall back to QR + payment redirect.

Build effort4–6 engineering weeks

Dedicated WhatsApp number per restaurant

WABA REGISTRATION PER OUTLET · PREMIUM TIER
Phase 2 · premium
Fragility · medium Replaceable: yes
What it unlocks

Messages come from "Filter & Co" not "Loop". More authentic, higher trust. Strong upsell for premium tier.

When it breaks

Registration takes 2–5 days per restaurant. WABA can reject for compliance. Backup: stay on shared number.

Setup cost (passed through)₹3,000 – ₹5,000 per restaurant
CPhase 3 integrations · month 9+

UrbanPiper

MULTI-CHANNEL ORDER AGGREGATION
Phase 3
Fragility · high
What it unlocks

Single integration for restaurants on Zomato + Swiggy + their POS. Same trigger pattern as Petpooja adapter.

Trade-off

Indirect dependency — UrbanPiper sits between us and the actual systems. If they change, we change. If Zomato changes UrbanPiper's feed, we still change. Acceptable for the reach.

Google Places API

REVIEW AUTO-VERIFICATION
Phase 3
Fragility · high
What it unlocks

Customer submits Google review → we check the API → reward fires without admin intervention. Removes the slowest manual queue.

Trade-off

Google API doesn't expose reviewer phone numbers. Identity matching requires manual heuristics. Partial automation — always falls back to manual.

Per API call~$0.005

Instagram Graph API

STORY / POST VERIFICATION
Phase 3 · maybe
Fragility · very high
What it could unlock

Auto-detect story tags, reel mentions. Eliminate the time-sensitive 6-hour SLA admin work.

Honest assessment

Meta has tightened Instagram API access dramatically. May not be feasible at all by the time we get here. Plan B: trusted-customer auto-approve covers most of this without any IG dependency.

RCS messaging

RICH CARD COMMS ON ANDROID
P3 watch
Fragility · medium
What it could replace

WhatsApp marketing messages on Android — richer, cheaper at scale, native to Google Messages.

Honest assessment

Not mainstream in India yet. Worth watching but not building until adoption is real. WhatsApp is the safe bet for now.
